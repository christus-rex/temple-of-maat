# Temple of SOL-OM-ON (Ma’at) — Visual Canon Foundation

## Purpose

This document defines the production and provenance standard for completing the 72-fold visual canon. It is intended to keep the Temple visually coherent, historically responsible, auditable, and maintainable as the archive grows.

## Canonical Chamber Package

Every chamber should ultimately expose the same four canonical visual layers:

1. **Final Seal** — the chamber’s canonical emblem for navigation, indexing, metadata, and archival reference.
2. **Invocation Seal** — a distinct contemplative or ritual-facing visual derived from the chamber’s documented symbolism. It must not be presented as an ancient artifact unless historically attested.
3. **Entity Depiction** — a high-fidelity depiction of the associated angel, figure, archetype, or symbolic intelligence, with historical status stated clearly.
4. **Chamber Artwork** — the broader environmental or narrative scene that expresses the chamber’s teaching, ethical function, and symbolic field.

The four layers should be visually related, but never collapsed into one overloaded image.

## Production Sequence

Use the following order for each chamber:

**Blueprint → Final Seal → Invocation Seal → Entity Depiction → Chamber Artwork → Metadata Audit → Archive Sync**

Do not advance a chamber to `CANONICAL_COMPLETE` until all required metadata and provenance checks pass.

## Batch Strategy

Complete chambers in reviewable batches of **6 or 12**.

Recommended cycle:

- Produce first-pass assets for one batch.
- Review legibility, symbolism, consistency, historical labeling, and file naming.
- Correct the template before propagating it to the next batch.
- Lock accepted assets as canonical and preserve rejected versions as non-canonical development artifacts where useful.

This avoids multiplying a design error across all 72 chambers.

## Provenance Layers

Every substantial claim, caption, metadata record, and interpretive note should identify its layer when relevant:

### 1. Historical Source
Material directly grounded in identifiable historical texts, manuscripts, archaeology, inscriptions, or documented traditions.

### 2. Traditional Interpretation
Interpretations established within a living or historical religious, mystical, philosophical, or esoteric tradition.

### 3. Comparative Correspondence
Cross-tradition parallels offered for study. Similarity must not be presented as proof of common origin, identity, prophecy, reincarnation, or hidden authorship.

### 4. Modern Temple Synthesis
Original Temple architecture, terminology, iconographic combinations, contemplative systems, and interpretive structures created in the modern project.

### 5. Personal Symbolism
User-specific correspondences, titles, gematria, visionary language, autobiographical meaning, and private or personal interpretive layers.

These layers may coexist in one chamber, but they must remain distinguishable.

## Discernment Standard

The Temple should preserve a consistent rule:

> Symbolic correspondence may suggest a question or contemplative relationship; it does not by itself establish historical identity, supernatural rank, authorship, prophecy, lineage, causation, or scientific fact.

Gematria, numerology, sacred geometry, visionary imagery, and comparative theology should remain reproducible and clearly labeled where used.

## Visual Standards

### Core presentation

- High-fidelity source assets.
- Balanced HDR with preserved highlight and shadow detail.
- Natural tonal contrast and restrained bloom.
- Fine material texture and strong perceived depth.
- Minimal on-image text.
- Typography must remain legible on mobile displays.
- No decorative text should override source accuracy.

### Visual identity

The Temple’s Ma’at palette may recur through turquoise, deep blue, white, and restrained gold, but chamber art should retain meaningful variation in palette, medium, composition, era, atmosphere, materials, and camera viewpoint.

Avoid forcing all traditions into one visual language.

### Cultural handling

- Preserve recognizable traditional attributes when historically appropriate.
- Distinguish reconstructed, comparative, and newly invented iconography.
- Do not present modern composite seals as archaeological finds or inherited ancient artifacts.
- Avoid visual claims of supremacy between traditions.

## File Naming

Recommended canonical pattern:

`CH###_<SHORT-NAME>_<ASSET-TYPE>_vMAJOR.MINOR.ext`

Examples:

- `CH001_VEHUiah_FINAL-SEAL_v1.0.png`
- `CH001_VEHUiah_INVOCATION-SEAL_v1.0.png`
- `CH001_VEHUiah_ENTITY_v1.0.png`
- `CH001_VEHUiah_CHAMBER-ART_v1.0.png`

Use stable chamber numbers even if display names or transliterations are later revised.

## Asset Status

Each asset should have one of these states:

- `DRAFT`
- `REVIEW`
- `REJECTED_NONCANONICAL`
- `CANONICAL`
- `SUPERSEDED`

Never silently overwrite a previously canonical asset. Supersede it with a new version and preserve provenance.

## Minimum Metadata Per Asset

Each canonical asset should record:

- Chamber number
- Canonical display name
- Asset type
- Version
- Creation date
- Source status / provenance layer
- Associated source references where applicable
- Short symbolic description
- Historical-vs-modern note
- Creator / authorship credit where appropriate
- Canonical file ID or path
- Archive / Drive ID when available
- Supersedes / superseded-by relation when applicable

## Grand Atlas Readiness

The future 72-Chamber Grand Atlas should be able to read structured chamber metadata rather than hard-coded prose.

Each chamber should eventually expose:

- chamber number and name
- seal thumbnail
- entity or archetype
- core teaching
- provenance layers
- gematria field where applicable
- source references
- audio / chant references
- full artwork references
- links to deeper codex material
- canonical asset status

The Atlas should function as the Temple’s primary navigational map, not merely as a decorative gallery.

## Definition of Done for a Chamber

A chamber is complete only when:

- all four canonical visual assets exist;
- naming and metadata are valid;
- source and synthesis layers are distinguishable;
- mobile legibility has been checked;
- the chamber does not rely on unsupported historical claims;
- final assets are archived without duplicates;
- the Grand Atlas can reference the canonical records;
- superseded drafts are not mistaken for current canon.

## Immediate Execution Plan

### Phase A — Foundation
- Adopt this provenance model.
- Define the canonical metadata schema.
- Select the first six chambers for production validation.

### Phase B — Pilot Batch
- Complete all four asset types for Chambers 001–006.
- Review visual consistency and source labeling.
- Correct the template before scaling.

### Phase C — Scale
- Continue in batches of six or twelve until all 72 are complete.
- Archive accepted assets immediately after validation.

### Phase D — Atlas
- Build the interactive Grand Atlas from canonical structured metadata.
- Add filters by chamber number, tradition, provenance layer, teaching, entity, source, and completion state.

### Phase E — Public Presentation
- Expose guided paths through the Temple while retaining the full research archive underneath.
- Keep publication and social distribution downstream of canonical preservation.

**Governing principle:** preserve the distinction between evidence, inherited tradition, comparative interpretation, modern synthesis, and personal symbolism while allowing them to remain in meaningful dialogue.
